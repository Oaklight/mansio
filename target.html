目标架构：core / web 拆分与契约层

本页是 core/web 重构的目标态，不是现状。现状见 实际架构。目标参照 llm-rosetta 的“core 包 + gateway/web 包”发布结构， 以及 Slack SDK 的组织方式：纯类型/契约单独成层，传输与界面只做解析和编排。

01包结构

三个发布包沿网络边界和依赖方向拆分。shared/ 不再作为独立目录存在： 它成为 mansio-core 的契约与类型层，由 core 包发布。

实线：运行期调用 带 import 标签：安装期依赖
mansio-client 只依赖 mansio-core 的契约与类型，不依赖 mansio-web； mansio-web 不依赖 mansio-client。这条规则取代当前的 shared/ 复制 + sync-shared.sh 机制。

03契约流：解析，而不是校验

所有跨进程数据先在 mansio_core.contracts 解析成类型化对象，再进入授权与 Bus； 响应同样由契约对象序列化。mansio-web 的路由只做“认证 → 解析 → 授权 → 调用 → 序列化”， 不持有业务规则。 

sequenceDiagram
  autonumber
  participant U as Admin UI / SDK
  participant W as mansio-web route
  participant K as mansio_core.contracts
  participant A as ChannelAuthorizer
  participant B as Bus

  U->>W: JSON / SSE 请求
  W->>K: parse(request) -> PublishRequest
  K-->>W: 类型化 DTO
  W->>A: authorize(user, channel, verb)
  A-->>W: allow / deny
  W->>B: publish(...)
  B-->>W: Message
  W->>K: serialize(Response / SSEEvent)
  K-->>U: JSON / event envelope
契约用途备注
Message, ChannelMeta, ACLEntry, ClaimResult, UserPresence领域对象从 shared/types.py 迁入 core
PublishRequest, QueryRequest, ChannelCreateRequest, QueueClaimRequest, ACLRequestHTTP 入参每个路由一个解析函数；非法输入在解析阶段返回 400
SSEEvent（event + data + id 信封）SSE 推送心跳、丢弃告警、截断告警都是显式事件类型
AdminView（stats / channels / messages / throughput / users / tokens / ACL）管理面板 JSON服务端返回视图模型，前端不拼装业务数据
*.schema.json契约的机器可读形式参照 llm-rosetta 的 shim_manifest.schema.json；用于文档与前端类型生成
这一步是“类型安全”的落点：类型定义在 core，边界只在一处解析，web 与 client 共享同一份契约， 不再各自复制 types.py / transport.py。

03bTransport：接口与实现分离

传输不是某一种协议，而是 core 定义的一组接口。客户端只依赖 Transport， 服务端只依赖 Frontend；HTTP/SSE 只是当前唯一的实现。 新增 WebSocket、Unix socket、进程内直连时，不改 SDK、CLI 或 MCP。

04管理前端结构

当前 admin.html 是 1952 行的单文件。目标结构参照 llm-rosetta 的 admin/： 页面骨架、样式、脚本、服务端路由分开；服务端下发类型化 JSON 视图，前端只负责渲染与交互。

关注点现状目标

服务端路由admin/server.py 755 行admin/routes/*.py，按资源拆分
数据形态临时 dict 拼装AdminView 契约 + JSON Schema
组件页面内自由发挥统一组件词汇（Slack Block Kit 式：声明式块 + 类型化字段）
依赖无仍然无运行时依赖；静态资源随包发布
